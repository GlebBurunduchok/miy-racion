# Структура проекта

Приложение без обязательных npm-зависимостей. Статический клиент открывается как сайт или как самостоятельный HTML. Серверный API дополняет клиент внешним каталогом.

| Слой | Файлы | Ответственность |
| --- | --- | --- |
| Интерфейс | index.html, styles.css, app.js | Страницы, диалоги, события, доступные подписи, адаптивная вёрстка |
| Основная логика | core.js, search.js | Профиль, валидация, расчёт целей, даты, поиск и импорт |
| Нутриенты | nutrition.js | Дополнительные значения, покрытие данных, проценты, цветовые диапазоны |
| Источники | providers.js, api.js | Нормализация внешних карточек, прямой/API-поиск, штрихкоды, загрузка подробностей |
| Хранение | storage.js | Чтение, миграция, проверка и запись состояния, сохранение повреждённого оригинала |
| Данные | data.js, strings.js, catalog.js | Переводы и встроенные продукты |
| Изображения | product-assets.js, product-photos.js, assets/ | Подробности примеров, исходные ссылки на фото, собственные иконки |
| Сервер | server.mjs, serve.mjs, Start.cmd | Только GET API, ограничения запросов, безопасная раздача публичных файлов |
| Сборка | project.config.mjs, build-single.mjs, scripts/service-worker.js | Единый список ресурсов, встроенный HTML, обновление кеша |
| Проверки | tests/, scripts/check.mjs | Логика, источники, хранение, сценарии DOM и локальный HTTP |

## Порядок загрузки

Данные и переводы → фотографии → core → search → nutrition → providers → storage → api → app. Порядок задаётся browserScripts в project.config.mjs; сборщик записывает его в index.html. Для самостоятельного HTML перед ними встраивается ZXing.

core экспортирует RationCore; search расширяет его поиском и импортом, nutrition — валидацией дополнительных полей и миграцией ориентиров. UI получает готовые функции и не хранит отдельную копию правил расчёта.

## Состояние

Единственный ключ дневника — mii-ratsion.v1. Внутри схема version:2: профиль, цели, настройки, дни, собственные продукты, избранное и веса. Дневниковая запись хранит снимок пищевой ценности, поэтому изменение исходной онлайн-карточки не меняет старые приёмы пищи. При загрузке подробностей редактируемой записи исходные четыре КБЖУ сохраняются.

Чтение и запись обёрнуты в обработку ошибок. Перед записью проверяется полное состояние. Неполные каталожные карточки допустимы в поиске, но не в дневнике. Повреждённый исходный JSON сохраняется в ключ .recovery перед заменой. При ошибке записи пользователь видит ошибку; последующие уведомления не подменяют её словом «сохранено».

## Внешние данные

Каждый продукт имеет устойчивый id и source. Фото связываются с исходной карточкой, а не только с похожим названием. Разрешены URL изображений известных источников. Отсутствие значения и числовой ноль различаются. Некорректный необязательный нутриент пропускается, не удаляя весь найденный продукт.

Поиск запускается после паузы ввода. Отменённые запросы и ответы прошлой поисковой сессии не могут заменить текущие результаты. Детали и фотографии загружаются ограниченной очередью. HTTP 404 штрихкода означает отсутствие записи; недоступность сервиса обрабатывается отдельно. Локальный сохранённый код имеет приоритет. UPC/EAN/GTIN с ведущим нулём приводятся к общему ключу сравнения.

## Сборка и выпуск

Редактируйте исходные файлы, затем выполните npm test. build-single.mjs создаёт Mii_Ratsion.html и sw.js, встраивает ресурсы и вычисляет отпечаток публичных файлов для кеша. Дополнительные зависимости для запуска проверок не нужны; DOM-среда для тестов включена с лицензией в tests/vendor/.

Проект не отправляет профиль и дневник поставщикам продуктов. Для внешнего поиска передаются поисковый запрос или штрихкод. Доступность внешних изображений и полнота источников не гарантируются приложением.
